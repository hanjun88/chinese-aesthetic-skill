# Context: 中式美学设计约束提取

## 背景

chinese-aesthetic-skill 负责将中式美学设计语言转化为可执行的技术约束。历史上出现过"设计意图模糊"、"视觉约束不可验证"、"实现参数与设计意图脱节"、"四层混淆（意图直接当参数）"等问题。本 Playbook 建立标准化的约束提取流程，确保从设计意图到验收到交付的全链路可追溯。

## HeartMirror 既定设计语言

### 色彩系统（六角色，必须完整分配）

| 角色 | 色彩 | 用途 |
|---|---|---|
| 青蓝为境 | 青蓝色系 | 环境基调、空间氛围 |
| 紫为玄 | 紫色系 | 神秘、深邃、玄奥 |
| 金为脉 | 金色系 | 结构脉络、装饰线条 |
| 白为息 | 白色系 | 呼吸感、留白、光 |
| 朱砂为印 | 朱红色 | 点睛、印章、重点标记 |
| 藤黄为生 | 藤黄色 | 生机、温暖、活力 |

### 美学特质

- 宋式温润：内敛、含蓄、质感细腻
- 晨曦天光：柔和、渐变、方向性光照
- 辽阔敬畏：大尺度空间、纵深、渺小感
- 中式巨构：宏大建筑、门体、结构美学

### 场景类型枚举

山门、宫殿、园林、宇宙入口、书院、禅院、市井、秘境

### 核心情感枚举

敬畏、宁静、庄严、神秘、悠远、温润、辽阔、肃穆

### 光照方向枚举

晨曦、黄昏、月夜、天光

## 四层分离（必须严格区分，跨层污染即 FAIL）

| 层级 | 含义 | 允许内容 | 禁止内容 | 示例 |
|---|---|---|---|---|
| 设计意图 | 想要表达的感觉和概念 | 纯描述性文字、场景类型、核心情感 | 具体色值、技术参数、数值 | "营造晨曦中的山门敬畏感" |
| 视觉约束 | 可观察的视觉特征 | 色彩名称、材质描述、光照方向、构图特征 | 具体色值（#RRGGBB）、数值参数 | "主色调青蓝，金色勾勒结构，光源来自左上方" |
| 实现参数 | 技术层面的具体数值 | HEX/RGB 值、角度、强度、分辨率、格式 | 主观描述（"好看"）、未替换占位符 | "ambientColor=#2a4a6a, keyLightAngle=30°, saturation=0.6" |
| 验收指标 | 可测量的通过标准 | 数值范围、阈值、检测方法、工具 | 模糊词（"好看""差不多"）、无检测方法 | "主色占比 > 60%，色温在 4000-5000K，无高饱和荧光色" |

## 禁用视觉倾向（必须可检测）

| ID | 名称 | 描述 | 检测方法 |
|---|---|---|---|
| CYBERPUNK | 赛博朋克默认视觉 | 霓虹光效、高对比未来感 | 风格分类器 + 霓虹色占比 |
| UI_CARD | UI 卡片化布局 | 圆角卡片、投影、按钮样式 | 几何形状检测 + 布局分析 |
| NEON_SATURATION | 高饱和荧光色泛滥 | HSV S>0.8 且 V>0.8 大面积使用 | 色域扫描 |
| FLAT_BACKGROUND | 缺乏空间尺度的平面背景 | 无纵深、无视差的纯平面 | 深度图方差分析 |
| DECORATION_ONLY | 仅有装饰性纹理而无结构 | 充满纹理但缺乏建筑结构 | 边缘检测 + 结构线条分析 |
| WESTERN_FANTASY | 西方奇幻风格 | 尖塔、魔法光效、哥特式建筑 | 风格分类器 + 建筑形态识别 |

## 约束

- 不得将设计意图直接当作实现参数（必须经过视觉约束层）
- 不得跳过视觉约束直接写代码
- 验收指标必须可测量，不得用"好看"等主观描述
- HeartMirror 色彩系统必须作为输入约束，六角色必须完整，不得随意替换
- 约束提取结果必须可被 design-compiler 消费
- 视觉约束层不得包含具体色值（#RRGGBB / rgb()）
- 实现参数层不得包含主观描述词
- 交付的约束包不得包含"待填充"占位符
- 禁用倾向必须有检测方法和阈值，不可检测的禁用项无效

## 术语

- **约束包（Constraint Package）**：合并四层内容的完整 JSON 文件，含 schemaVersion、source、layers、validation
- **四层分离（Four-Layer Separation）**：设计意图/视觉约束/实现参数/验收指标的严格内容边界
- **跨层污染（Layer Contamination）**：某层包含其他层的内容（如视觉约束层含具体色值）
- **可检测（Detectable）**：禁用倾向有明确的检测方法、工具和阈值
- **HeartMirror 枚举（HeartMirror Enums）**：场景类型、核心情感、光照方向等既定可选值集合

## 前置条件

1. 设计意图已明确（文字描述文件存在且非空）
2. HeartMirror 设计语言文档可查阅
3. 场景类型和核心情感已定义（在 HeartMirror 枚举中）
4. 技术约束（分辨率、运行时）已知
5. 工具链（jq / sha256sum / stat / mktemp / grep）均可用

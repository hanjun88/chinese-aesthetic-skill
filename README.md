# Chinese Aesthetic Design Skill

> 为 HEARTMIRROR Act 0 提供中式传统建筑与美学的可执行约束。不是"贴中国元素"，是从结构层面回答"这个设计为什么是中国的"。

## 定位

本 Skill 嵌入设计管线：

```
finesse-brief（需求规格）
  → chinese-aesthetic-skill（中式美学约束）← 本 Skill
    → finesse-skill（界面设计执行）
      → frame-smith（动效执行）
        → finesse-term（术语对齐）
```

本 Skill 是**美学知识的单一来源**：规则、阈值、出处与置信度登记在机器登记簿 [`rules/`](rules/)，已登记的阈值由引擎直接读取，文档只引用、不重复。
对外的机器输出是 **AestheticConstraintSheet** 约束交接产物（见下文「约束交接产物」）。

## 安装

**运行要求**：Node.js 18.20 及之后的 18 线，或 20.10 及之后（精确范围见 `package.json` 的 `engines`）。引擎经 JSON import attributes（`with { type: 'json' }`）读取 `rules/` 登记簿，这两条线上更早的版本无法加载 `lib/`。

```bash
# 方式一：Impeccable / CLI
npx skills add git+https://github.com/hanjun88/chinese-aesthetic-skill.git

# 方式二：克隆到本地 skills 目录
git clone https://github.com/hanjun88/chinese-aesthetic-skill.git ~/.skills/chinese-aesthetic-skill

# 方式三：npm 包（Node.js 项目中直接 import）
npm install github:hanjun88/chinese-aesthetic-skill
```

## 使用方法（快速开始）

### 对话调用

```
@ChineseAestheticSkill 请根据当前 ACT0 云海+单门场景，应用中式配色、比例和交互规则
```

### 约束交接产物（AestheticConstraintSheet）

本 Skill 是美学知识与建议/生成的权威：`scripts/emit-sheet.mjs` 为每个设计上下文生成 **AestheticConstraintSheet**，每条约束都带 `rule_id`、`decision_id`、置信度与出处（`source_ref → rule_id → decision_id`），数值全部来自登记簿 `rules/`。本 Skill 只生成约束，不实现、也不执行编译器逻辑。

**跨仓绑定：DEFERRED / UNBOUND。** 本仓库不钉扎任何编译器 commit、schema 版本或契约哈希，也不把其中任何一个当作权威；产物里的 `binding.status` 就是 `UNBOUND`。只有独立的 binding 任务决定并验证了消费方 schema 之后，这一状态才会被替换。

```bash
node scripts/emit-sheet.mjs --list     # 有效的与被排除的设计上下文
node scripts/emit-sheet.mjs --period SONG --material STONE --lighting DIM --scene-type OBJECT_STUDY
```

## 核心引擎（10个可执行决策引擎）

本 Skill 的核心不是规则手册，是**可执行的决策引擎**。每个引擎输入设计参数，输出判定结果或生成方案。

```javascript
import { chineseness, clicheDetector, colorEngine, fullAssessment } from 'chinese-aesthetic-skill';

// 1. 判定"这个设计为什么是中国的"（10维评分 + 结构东方性测试）
const result = chineseness.assessChineseness({
  voidRatio: 0.65,
  colors: ['#E8E4D9', '#2C3E50', '#B8860B'],
  brightnessRatio: 4,
  buildingToHumanRatio: 10,
});
console.log(result.score, result.level, result.coreAnswer);
// → score（0-100）、level（master / authentic / surface / western-structure / not-chinese）、coreAnswer（一句话归因）

// 2. 反俗套检测（国潮贴图/古装影视/仿古景区/AI国风）
const cliches = clicheDetector.detectCliches({
  patternCoverage: 0.25,
  colors: ['#FF0000', '#FFD700'],
});
// → { overallScore, pass, clicheTypes, violations, recommendations, ... }

// 3. 生成配色方案（五方正色 + 君臣佐使70:20:10）
const scheme = colorEngine.generateColorScheme({ preset: 'act0-cloud-gate' });
// → { colors: { main, secondary, accent, background }, ratio, ... }

// 4. 一站式综合评估（运行所有10个引擎）
const full = fullAssessment(design);
// → { overallScore, overallPass, level, coreAnswer, engines, recommendations, ... }
```

结构东方性测试会列出成立的结构信号，例如「留白≥50%」；它是引擎的计分信号（规则 `CAS-VS-SS-001`），不是合规线。<!-- rule:CAS-VS-SS-001 -->

| 引擎 | 核心能力 | 输入 → 输出 |
|---|---|---|
| **chineseness** | "为什么是中国的"判定 | 设计参数 → 10维评分(0-100) + 结构东方性测试 + 核心回答 |
| **clicheDetector** | 四类俗套自动检测 | 设计参数 → 俗套类型 + 评分 + 违规项 + 修复建议 |
| **spatialEngine** | 空间秩序生成器 | 场景类型/尺寸 → 中轴/开间/层级/尺度/进深/虚实分配 |
| **colorEngine** | 色彩决策器 | 场景/情绪 → 五方正色选择 + 君臣佐使比例 + HEX色值 |
| **lightEngine** | 光影决策器 | 时间/场景 → 光源类型/角度/强度 + 阴影 + 体积光 + 暗部色 |
| **interactionEngine** | 交互语义映射器 | 用户动作 → 东方意象响应 + 动画参数 + FSM状态转换 |
| **proportionEngine** | 比例校验与生成器 | 尺寸参数 → √2/三段式/出檐/巨构比例合规性 + 推荐值 |
| **materialEngine** | 材质决策器 | 元素类型 → PBR材质参数(color/roughness/metalness) + 风化包浆 |
| **antiAIArtifacts** | AI生图伪影检测与消除 | 生图参数 → 风险评分 + 三类伪影（超自然细节/不可能光照/完美对称）+ 修复策略 |
| **videoMotionEngine** | 视频动势决策器 | 情绪/时长 → 相机运动 + 剪辑节奏 + 情绪曲线 + 生图/放大/后期参数 |

## 十大核心规则

| # | 规则 | 优先级 | 一句话 |
|---|---|---|---|
| 1 | 空间秩序 | P0 | 中轴为骨，层级递进；主元素偏离中轴过大判FAIL（容差见 guidelines/spatial-order.md） |
| 2 | 虚实关系 | P0 | 留白是画面的一部分，虚大于实；亮调山水的留白由规则 `CAS-VS-HF-001` 约束（P0），`CAS-VS-SS-001` 只是引擎计分信号，数值见下方登记簿表 |
| 3 | 比例 | P0 | 方五斜七(√2)；偏离经典比例过大判FAIL（容差见 guidelines/proportion.md） |
| 4 | 材料 | P1 | 木石土金纸的真实感，禁塑料感 |
| 5 | 光影 | P1 | 柔光分层，禁硬光斑和聚光灯 |
| 6 | 色彩 | P0 | 五方正色体系，禁霓虹色 |
| 7 | 动势 | P1 | 云流旋生长，禁弹跳粒子特效 |
| 8 | 时间感 | P1 | 风化昼夜变化，禁全程静止 |
| 9 | 禁忌 | P0 | 禁皇家符号滥用、禁廉价感 |
| 10 | 交互语义 | P0 | 鼠标扰动云海、点击生长、滚动下潜 |

## 规则登记簿（关键决策）

规则、阈值、出处与置信度的**单一来源**是 [`rules/`](rules/)：引擎经 `lib/rules/` 读取已登记的阈值，消费方经 AestheticConstraintSheet 交接产物获取它（跨仓绑定 DEFERRED / UNBOUND），文档不得再写第二份。
下表由 `npm run docs:render` 从登记簿渲染（`npm run docs:check` 校验无漂移，`npm run lint:docs` 禁止文档重复阈值或手写测试计数）。
改数值只改登记簿，再重新渲染。尚未登记的判据（饱和度、材质粗糙度、动效时长等）暂以 `guidelines/` 的原文和引擎内部判据为准，由登记簿逐族接管。

- 留白（`void_ratio`）有三种语义，各有自己的规则：**HARD_FLOOR**（P0，亮调山水）、**PERIOD_BAND**（朝代先验区间，取证据的并集而非平均值）、**STRUCTURAL_SIGNAL**（只给引擎计分，不是合规线）。**DESIGN_DEFAULT** 是各场景类型的生成默认值，会被钳制进上下文的有效区间。证据与决策见 [`docs/decisions/ADR-0001-negative-space.md`](docs/decisions/ADR-0001-negative-space.md)。
- 区间是先验而非绝对：同一参数的朝代区间、物理范围与 HARD_FLOOR 相交得到有效区间；交集为空的上下文被拒绝（`rules/vocabulary.json` 的 `excluded_contexts`），而不是随意选一个赢家。
